# Justificación Patrones de Diseño

## Factory (creacional)
Utilizamos factory para distintas instancias de centro de vacunación, esto es útil pues resuelve el problema de instanciar según tipo de centro de vacunación, factory nos permite manejarlas como parte del mismo tipo objeto, pero donde cada una tiene propiedades adicionales. Lo que es eficiente a la hora de gestionar historial, agendar horas, etc. Se descartó la opción de utilizar singleton, lo que estaba pensado para manejar un mismo tipo de usuario para externos al sistema (usuarios que no se han registrado).

## Observer (comportamiento)
En nuestro proyecto, confirmar cita dispara varios eventos al mismo simultaneamente. Lo que puede dificultar la legibilidad del código a medida en la que aumenta su complejidad, una solución para esto es utilizar observer, de modo que nuestro controlador maneja citas, y los métodos concretos se activan al confirmar las citas. Es decir, el patrón se activa en el momento en que confirmarCita() cambia el estado de la cita. Es en ese instante que notificarObservers() dispara los dos suscriptores: NotificacionCorreo envía el correo con los datos de la vacunación, y HistorialUsuario registra la cita. Antes de esa confirmación, los observers están suscritos pero inactivos.

## Proxy (estructural)
El Virtual Proxy resuelve el problema de instanciación anticipada de objetos costosos de acceso a base de datos: sin el patrón, HistorialServiceImp, VacunacionServiceImp y AuthServiceImp se crearían al iniciar el sistema aunque el usuario nunca llegue a usarlos, generando conexiones innecesarias a BDD. La alternativa de instanciarlos directamente desde las clases del dominio fue descartada porque acopla Persona, Cita y Usuario a implementaciones concretas. En el diagrama, los proxies se ubican como intermediarios entre esas clases de dominio y las implementaciones concretas, compartiendo la misma interfaz Service para que el cliente no perciba diferencia. En el flujo, cada proxy se activa de forma diferida: recién cuando el sistema ejecuta confirmarCita(), buscarVacunacion() o autenticar() por primera vez, el proxy correspondiente crea la implementación y delega la llamada, dejando sin instanciar los otros dos si el flujo de esa sesión no los requiere.
